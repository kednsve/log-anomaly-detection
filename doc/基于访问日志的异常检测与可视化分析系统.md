# 基于访问日志的异常检测与可视化分析系统

系统上传 CSV 格式的 Web 访问日志，完成脏数据处理后存入数据库，支持日志与告警的分页查询、条件筛选和处理状态跟踪。异常检测采用「规则 + 无监督模型」两层机制：规则层负责高频访问、大量 404、认证失败等可解释的硬规则；模型层由 Python 服务使用 Isolation Forest 对 IP 级行为特征做异常检测。两层结果合并后写入 `access_log` 并生成告警。

当前状态：

- Java 后端的登录、CSV 异步上传、日志/告警查询更新、规则检测已实现；
- Python 侧的数据生成、特征工程、Isolation Forest 离线训练与跨文件评估已实现，模型保存为 `models/isolation_forest.joblib`；
- Python 推理接口、Java↔Python 联调、统计接口和 Vue 前端尚未实现；
- 原设计中的慢响应规则已移除，因为当前合成数据没有真实的慢速攻击样本。

## 三、异常检测机制

### 1. 规则层（已实现）

按 `upload_task_id` 聚合每个 IP 的总请求数、最后访问时间、404 数、401/403 数和单分钟峰值，执行三条规则：

| 规则 | 条件 |
| --- | --- |
| 高频访问 | `peakPerMinute >= 60 && totalRequests >= 60` |
| 大量 404 | `count404 >= 10 && ratio404 >= 0.2` |
| 认证失败 | `totalRequests >= 20 && authFailureRatio >= 0.5` |

检测入口为 `POST /Detect/run?taskId=`。`DetectServiceImpl` 在检测前用条件 UPDATE 原子抢占 `upload_task.rule_detect`（0/2/3 → 1），成功后置 2、失败置 3；`RuleResultWriter` 在事务中重置规则标记、删除旧告警、按 IP 回写并插入 `alert`。

### 2. 模型层（离线训练完成，推理接口未实现）

- `core/features.py` 把请求级日志聚合成一行一个 IP 的 25 个特征：请求量/活跃分钟/分钟峰值、404/401-403/5xx/200 比例、URL 路径唯一数与熵、方法比例、响应时间统计、字节/连接时长、夜间占比、请求间隔统计；
- `train/train.py` 使用 6 个文件的 train/demo/truth 做留一文件交叉评估：5 个文件训练，剩余文件的 demo 测试；模型为 `IsolationForest(n_estimators=300, contamination=0.12, random_state=42)`；
- 训练时不使用 truth 标签，truth 仅用于评估；
- 当前一次 30k 数据、`contamination=0.12` 的评估结果：平均 Precision 0.742、Recall 0.916、F1 0.802、AUC 0.995、PR-AUC 0.961；Botnet、BruteForce、Infiltration、WebAttack 基本全部检出，DDoS 召回 74.4%；
- 模型 bundle 包含 `model`、`features`、`contamination`、`random_state`、`n_estimators`、`train_stems`、`train_samples`、`n_features`、`offset`；
- 推理接口计划为 `POST /detect`：Python 读取指定任务的 `access_log`，返回每个 IP 的 `score` 和 `abnormal`；Java 负责写回 `model_score`、`model_abnormal`、`final_abnormal`，并合并告警。

两层结果合并后：

```text
final_abnormal = rule_abnormal OR model_abnormal
alert_source   = rule / model / both
```

`upload_task.model_detect` 已预留，但当前保持 0，等待推理接口和 Java 接入。

## 四、数据集与数据生成

本地 `data/` 存放 6 个 CIC-IDS2018 日文件：Wednesday1、Friday1、Wednesday2、Friday2、Thursday1、Friday3。`clean_data.py` 读取每条流的 `Dst Port, Protocol, Timestamp, Flow Duration, TotLen Fwd Pkts, TotLen Bwd Pkts, Label`，清洗、去重后生成：

- `<stem>-train.csv`：按时间前 70%；
- `<stem>-demo.csv`：后 30%；
- `<stem>-truth.csv`：IP 级真值（是否攻击、攻击类型、请求数）。

当前采样参数：

- `SAMPLE_SIZE=30000`（`config.py`）；
- 攻击行最多占 30%（9000 行），正常行补足；正常不足时少输出，不再用攻击补足；
- 正常流和攻击流分开做端口过滤，正常流 HTTP 端口不足时回退到全部 TCP/UDP 端口并映射为 80；
- 正常流按 5 分钟切会话，攻击流按 10 分钟切 campaign，每块最多 20 行；
- 块分配给 200 个正常 IP 画像和 20 个攻击 IP 画像；攻击流优先保证每个攻击画像至少一个块。

数据限制：

- 慢速攻击行为不真实，慢响应规则已移除；
- truth 只记录有请求的 IP，正常 IP 通常少于 200 个；
- train/demo 按时间切分，同一 IP 可能同时出现，因此模型采用跨文件评估。

## 五、数据库表

| 表 | 说明 |
| --- | --- |
| `user` | 管理员账号，BCrypt 密码 |
| `upload_task` | 上传任务、行数统计、失败明细、上传状态、`rule_detect` / `model_detect` 检测状态 |
| `access_log` | 访问日志与网络流字段，含 `rule_abnormal` / `model_score` / `model_abnormal` / `final_abnormal` 三层标记 |
| `alert` | 每个异常 IP 一条告警，`alert_source` 为 `rule` / `model` / `both`，带处理状态；有 `(task_id, ip)` 唯一约束 |

## 七、运行方式

```bash
# 1. 初始化数据库
mysql -u root -p < sql/init.sql

# 2. 启动 Java 后端（backend/log-anomaly-detection/）
mvn spring-boot:run

# 3. 生成清洗数据（backend/detection-service/）
.venv/Scripts/python.exe clean_data.py

# 4. 训练模型
.venv/Scripts/python.exe -m train.train --contamination 0.12
```

Java 接口默认监听 `http://localhost:8080`，除 `/login` 外需要 `Authorization: Bearer <token>`。Python 的 `uvicorn main:app --port 8000` 目前仍是 Hello World 桩。
