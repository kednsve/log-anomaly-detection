## 四、与后端接口的对应关系

后端已实现的接口可以直接使用：

| 页面功能 | 后端接口 |
| --- | --- |
| 登录 | `POST /login`，请求体 `{username, password}` |
| 上传 CSV | `POST /uploadTask/csv`（multipart `file`） |
| 上传进度 | `GET /uploadTask/polling?taskId=` |
| 上传记录 | `GET /uploadTask/query` |
| 日志列表 | `GET /AccessLog/query` |
| 告警列表 | `GET /Alert/query` |
| 处理告警 | `PUT /Alert/update` |
| 触发检测 | `POST /Detect/run?taskId=` |

除登录外，请求需携带 `Authorization: Bearer <token>`。建议在 `api/request.js` 的请求拦截器中统一注入 token，并在响应为 401 时跳转登录页。

任务列表与轮询结果中的 `rule_detect` / `model_detect` 分别表示规则层、模型层检测状态（0 未检测、1 检测中、2 完成、3 失败）；任一为 1 时禁用「触发检测」按钮。

## 五、待补充的后端能力

可视化大屏和统计报表依赖以下尚未实现的接口：

- 访问趋势（按时间分桶的请求数/异常数）；
- IP 访问 TOP、URL TOP；
- 归属地分布；
- 异常统计（规则/模型/最终异常数量、告警处理状态分布）；
- 报表导出。

这些接口需要在后端新增 `StatsController` / `StatsService` 后再对接。
